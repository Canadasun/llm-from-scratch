# Training recovery, November 14

Branch: `fix/sft-training-integrity`, starting at `a3c0cca`.

The accepted Phase 4 base remains accepted. Phase 5's two failed candidates and
the Phase 6 preview gate failures remain failures. No deployment was changed.

## Findings and fixes

- SFT resume used unrestricted pickle loading. It now uses `weights_only=True`.
- Resume checked only the base and instruction manifest. It now also checks the
  actual instruction split hashes, replay identity, sampling, learning schedule,
  optimizer configuration, device type and precision before restoring state.
- GPU dropout RNG was not checkpointed. CUDA RNG states are now saved/restored.
  CUDA execution still needs validation on the free GPU worker.
- Instruction manifests were hashed without verifying their split contents.
  Declared train/validation hashes are now verified before loading the model.
- Zero accumulation/evaluation intervals and invalid replay fractions are rejected.
- The installed CPU environment has PyTorch 2.2.2, below the declared requirement.
  Its missing `torch.amp.GradScaler` prevented training. A fallback to the older
  CUDA AMP scaler enables this local environment without changing modern behavior.

Older SFT resume files lack the newly required integrity metadata and are rejected.
Existing inference checkpoints still load. Start a fresh candidate from the accepted
base rather than silently accepting an unverifiable resume configuration.

## Real checkpoint pilot

Evidence: [machine-readable record](integrity-pilot-2026-11-14.json).
The base hash matches the accepted step-8,000 artifact. Measured parameter count
is 70,224,640 (earlier phase documents approximate it as 65M).

The pilot retained the original repository splits from `sft-v3`, selected only
implementation rows that parse as Python and fit 256 tokens, and sampled with seed
2026: 64 training examples and eight validation examples. Parsing does not prove
functional correctness. No evaluation or private-holdout data entered training.

Eight CPU steps used batch one, accumulation two, learning rate 1e-5, two warmup
steps and 20% base-corpus replay. Training took 22.8 seconds after initialization.

it is not a release candidate and was not promoted.
